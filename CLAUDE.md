# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Two Zig executables for timecards from Open Compute's Time Appliance Project (Facebook/Meta Timecard, Celestica, Orolia ART Card, Adva): `tapctl`, a CLI for one-off actions, and `tap-monitor`, a long-running process meant for a systemd service, reporting with OpenTelemetry. They read the Linux `ptp_ocp` driver's sysfs (`/sys/class/timecard/ocp<N>`) and the matching `/dev/ptp<N>` character device.

## Commands

The project targets Zig **0.17.0** (`build.zig.zon` `minimum_zig_version`). Dependencies are fetched into a project-local `zig-pkg/` folder, which is gitignored. To update one, run `zig fetch --save=<name> "git+https://...#<commit-or-tag>"`.

```sh
zig build                         # builds zig-out/bin/tapctl and zig-out/bin/tap-monitor (Debug)
zig build --release               # ReleaseSafe (preferred_optimize_mode)
zig build run -- info -N 1        # run tapctl with args
zig build run-monitor -- -N 1     # run tap-monitor with args
zig build test                    # unit tests of the `tap` library module (src/root.zig), then e2e
zig build e2e                     # end-to-end: `tapctl --root <fake root> info` on test/fixtures and test/failures
zig build docs                    # emits docs to zig-out/docs
zig test src/serialnumber.zig --test-filter parseSerialNumber   # single test, only for files that import nothing beyond std
```

Zig only collects tests from files that a test block references. When you add a source file to the `tap` module, add it to the `test { _ = @import(...); }` block at the end of `src/root.zig`, or its tests are silently skipped. `zig build test` works natively on any OS (see `test/port.zig` below). The executable's own tests (src/cmd/control.zig) are commented out in `build.zig`.

The program only works on Linux with a real timecard present. It needs Linux ≥ 6.9 (the tty attributes are grouped in a `tty/` folder) and root access to open `/dev/ptp<N>`. Other OSes are not supported. Building for them (for example macOS) only exists so that tests run on a development machine. To check the real Linux build, cross-compile with `-Dtarget=x86_64-linux-gnu` (or `aarch64-linux-gnu`). On an Apple Silicon host, the resulting binary (or test binary from `.zig-cache/o/*/test`) can be run in an aarch64 Linux container. `zig build e2e` covers most needs without a container.

## Architecture

- **`src/cmd/control.zig`**: `tapctl`, the CLI only. `main` takes a `std.process.Init` and passes `init.io` down to everything that touches the filesystem or network. It parses arguments with `zig-args` (`parseWithVerbForCurrentProcess`). The verbs are the `Verbs` union: `info` and `mro` (a stub), one-off actions. Help text is built from each options struct's `meta`. To add a verb, add an options struct, a `Verbs` field, a line in `CommonOptions.meta.full_text`, and a branch in the help and dispatch `switch`es.
- **`src/cmd/monitor.zig`**: `tap-monitor`. It reports the PTP offset as the OpenTelemetry observable gauge `timecard.ptp.offset`, read by a callback at each export (`OTEL_METRIC_EXPORT_INTERVAL`, 10s unless set), and exports its logs over OTLP too. The SDK does not export the types of observable instruments, so they are recovered with `@typeInfo` from `Meter.createObservableGauge`. The periodic reader is created after the timecard and stopped before it is freed, since its last export reads it. A failed reading sets an `Io.Event` that `main` waits on, so the process exits for systemd to restart it. The SDK (open-telemetry/opentelemetry-zig) is configured from the standard `OTEL_*` environment variables, and set up before looking for the timecard so that startup errors reach the collector too. Its own logs go through `Log.emit` with `@src()`, straight to an OpenTelemetry `Logger`, so that they carry their source location. Its `logFn` handles the `std.log` calls of the shared code: it exports only the scopes of this repository (`.timecard`, `.cli`) and writes everything to stderr. The SDK logs its own failures with other scopes, and exporting those could loop.
- **`src/cmd/cli.zig`**: the command line code shared by both executables, which import it by path: turning the card selection options into an opened `Timecard`. Code of `src/cmd/` is internal to the executables, while `src/` is the `tap` library. Their options structs declare the same fields (`ocp-number`, `timecard-name`, `timecard-path`, `root`), since `zig-args` structs can't be composed. `build.zig` gives each executable its own `build_info` (name and version), through `addExecutable` and a `Program` description.
- **`src/root.zig`**: the `tap` library module, which the exe imports as `tap`. `Timecard.fromPath` collects everything from sysfs into one struct. All paths are opened relative to a root `Dir` (`--root`, `/` by default), and `/dev` is reached the same way in `ptp.zig`, so never use `openDirAbsolute`. `Timecard.to_json` builds a `std.json.Value` by hand, using an arena. The JSON shape is the output contract of `tapctl info` (see the README examples). Any new field must be added both to the struct (filled in `fromPath`) and to `to_json`. `Timecard` stores the `Io` it was created with, because `deinit` needs it to close the PTP device. `std.json.ObjectMap` is unmanaged, so `put` takes the arena.
- **`src/ptp.zig`**: talks to `/dev/ptpN` with raw `ioctl`s (`PTP_CLOCK_GETCAPS`, `PTP_PIN_GETFUNC`, `PTP_SYS_OFFSET_EXTENDED`). The header is translated by the build system (`addTranslateC` in `build.zig`, since 0.17 has no `@cImport`) and imported as the `ptp_clock` module. The ioctl request constants are `@truncate`d to `u32` for `std.c.ioctl`. `readOffset` subtracts a hard-coded 37s TAI-UTC offset. On non-Linux targets, `build.zig` uses `test/port.zig` as that module instead. It's a hand-written, test-only stand-in with the same struct layouts, so any new declaration used from `ptp_clock` must also be added there. It also fakes the ioctls (`ptp.zig` picks `linux.ioctl` when the module declares one) by parsing the PTP device as a ZON file. Its `offset` field gives the PTP clock's time relative to the system's, for the offset readings of `tap-monitor`. The e2e executable always uses this stand-in, even on Linux.
- **`src/pci.zig`**: maps PCI vendor and device IDs to enums. Their `@tagName`s are the display strings, hence names like `@"ART Card"`.
- **`src/readfile.zig`**: helpers for reading sysfs attributes (an integer, or a space-separated list) that log a descriptive error on failure. Pass `.mandatory = false` for optional attributes so no error gets logged.
- **Logging**: the `tap` library logs with `std.log.scoped(.timecard)` and never chooses where logs go: each executable does, through `std_options.logFn`. `tapctl` configures the upstream `axe` library (Ratakor/axe, pinned by release tag) at the top of `src/cmd/control.zig`, and only the executable depends on it. `std.log` carries no source location, so messages of the shared code must be clear on their own.
- **`test/fixtures/<card>/`**: fake roots for `--root`, modeled on real cards. Each has a `sys/` tree laid out like real sysfs (`class/timecard/ocpN` and the `device`/`ptp` links are relative symlinks into `devices/pci...`) and `dev/ptpN` as a ZON description of the clock's capabilities and pins. Sysfs attributes end with a newline, except the `tty/` ones, as the driver emits them. To add a fixture, also list it in the `cases` array in `build.zig`, where it must exit 0.
- **`test/failures/<name>/`**: fake roots reproducing one known problem each, copied from the ART fixture with its timecard renamed `ocp0` (so no `--ocp-number` is needed) and a single change: `pci-delay-estimation` (the `ts_window_adjust` driver bug), `unflashed-eeprom` (serial number bytes that aren't ASCII digits), `linux-6.8` (tty symlinks instead of the `tty/` folder). Their `cases` entry expects an exit code and a stderr substring proving tapctl reported the problem. When generating such trees, build paths relative to the repo and check they stay inside it: they mirror `/sys` and `/dev`, so an empty prefix would target the real root filesystem.
- **`test/no-sudo.zig`**: git doesn't store file permissions, so the root of the forgotten `sudo` failure is generated at build time into `.zig-cache`: a `sys` symlink to the Facebook fixture's, and a `dev/ptp1` that only root can open. The case is skipped when the build runs as root, which can open it anyway.

## Conventions

- Structs and helpers take an allocator and provide `deinit(gpa)`, without knowing whether an arena is used. Name the parameter `alloc` when it may be either an arena or a general purpose allocator, and `gpa` when it has to be a general purpose allocator (`deinit`, the backing allocator of an arena). `Timecard` owns an arena: `fromPath` allocates everything in it, and its `deinit` frees the arena at once instead of calling the sub-structs' `deinit`. Do all allocations in `fromPath` before copying the arena into the result. Resources other than memory still need releasing: `PtpInfo.close` releases the device without freeing memory, and `PtpInfo.deinit` does both. `main` uses `init.gpa`, which leak-checks in Debug builds only (because libc is linked).
- Sysfs attributes that only exist on some cards or kernel versions (for example `clock_source`, `available_clock_sources`, `serialnum`) are optional fields (`?T`). Failing to read them gives `null` and does not abort, and `to_json` leaves the key out.
- Trust kernel guarantees (the sysfs one-page limit, attributes being regular files, PTP core validation such as pin functions, UAPI layouts), but not what the `ptp_ocp` driver outputs, because it has had bugs. That covers attribute contents and names and the pin descriptors the driver fills. Validate those and fail or warn gracefully, and keep `assert` for kernel guarantees. Read sysfs attributes with `readFileFitting` into a `[max_attribute_size]u8` buffer (from `readfile.zig`), never into a buffer sized from what the driver is expected to print.
- Known hardware and kernel quirks get a log message that tells the user how to fix them. For example, `ts_window_adjust` overflows on Linux 6.12 to 7.2, fixed in 7.3 and in the October 2026 stable updates by upstream commit `f8c8bd159a9b` (fix: write `0` to it).
